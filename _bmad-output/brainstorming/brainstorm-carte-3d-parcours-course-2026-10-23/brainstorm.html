Le ruban 3D pré-cuit : la première architecture

Le coach pose une proposition complète et séduisante : ne pas servir de terrain, mais découper une bande de relief autour de la trace et la pré-cuire au build.

  • CoachPas une carte mais un ruban : mesh extrudé du MNT (SRTM 30 m / Copernicus) découpé sur ~500 m de large autour de la trace GPX. Poids divisé par 50 face à une tuile de terrain complète.
  • CoachPipeline build-time, pas runtime : GPX → script Node → .glb Draco + hillshade / hypsométrie cuits en texture. Quelques Mo, versionnés par course, mis en cache PWA une fois pour toutes.
  • CoachMesh pré-cuit ⇒ l'animation devient un suivi de spline : trace GPX en Catmull-Rom, caméra paramétrée par l'abscisse curviligne s. Une seule variable d'état.
  • CoachInsight : s devient le bus d'état partagé — profil altimétrique, checkpoints si, position live du coureur s(t) depuis le dernier scan, tous sur la même timeline.
  • Coach3D facultative : fallback profil 2D en SVG sur la même donnée (s, altitude) si WebGL est absent, la machine faible ou la batterie basse. Progressive enhancement.
  • CoachExagération verticale ×1,5 à ×2 du relief (comme Relive ou Strava Flyby), sinon un trail paraît plat.
  • ArbitrageArbitrage pressenti : three.js + .glb pré-cuit plutôt que MapLibre terrain 3D — les tuiles raster-dem semblent trop lourdes à servir hors-ligne.

Le virage UTMB : la référence qui tue le ruban

Le Boss apporte une référence visuelle concrète. Le coach l'ouvre et constate que la technique derrière n'est pas celle qui venait d'être choisie.

  • BossRéférence visuelle : la page parcours de l'UTMB Mont-Blanc. Cible = deux vues — carte 2D interactive avec points de passage + profil altimétrique — en version allégée, pas toutes les fonctionnalités.
  • BossCible précisée par captures : (1) profil altimétrique schématique avec checkpoints, services, barrières horaires, segments km / D+ ; (2) vue 3D relief avec imagerie satellite et marqueurs de checkpoints.
  • CoachLa 3D de l'UTMB n'est pas un ruban pré-cuit : c'est du terrain tuilé complet — Mapzen terrain-RGB + ortho swisstopo/IGN — façon MapLibre/Mapbox terrain. L'arbitrage three.js + glb est remis en cause.

Les surfaces et la position live

Avant de choisir une pile, il faut savoir pour qui. Le Boss fixe deux cibles ordonnées ; le coach en fait apparaître une troisième.

  • BossDeux cibles, dans cet ordre : (1) site vitrine en ligne (épopée 2) pour que les coureurs préparent le parcours en amont ; (2) app coureur (épopée 6) avec synchro offline/online, le coureur remonte sa position dès qu'il capte et apparaît sur un écran live.
  • CoachTroisième surface implicite : un écran live — grand écran PC course ou public — qui affiche les coureurs sur la carte.
  • BossPosition live = GPS du téléphone avec un ping toutes les 10 minutes, pas de temps réel, en plus des scans aux checkpoints de l'épopée 4. Deux sources fusionnées.
  • CoachUn ping toutes les 10 min rend la trace brute trop creuse pour animer : projection sur l'abscisse curviligne s de la trace officielle + interpolation entre pings = position plausible en continu.
  • ArbitrageDécision : entre deux pings, point figé sur le dernier s connu + horodatage « vu il y a X min ». Le plus simple techniquement : pas d'extrapolation, pas de faux positif, pas de boucle d'animation.
  • BossPiste explorée : exploiter les données Strava ou les données de montre Garmin.
  • CoachStrava et Garmin fournissent des traces d'activité, pas un fond de carte 3D — ils ne remplacent pas MapLibre/Mapbox. L'API Strava interdit de stocker ou d'afficher les traces d'autrui ; l'API Garmin Connect suppose un partenariat à demander. Garmin LiveTrack couvrirait le live mais dépend de la montre du coureur et du réseau.

Le terrain algérien : pas de swisstopo en Kabylie

La contrainte majeure de la session. Ce que l'UTMB obtient d'agences nationales n'existe pas ici — il faut redescendre sur des sources mondiales libres, puis vérifier qu'elles couvrent réellement Yakouren.

  • Coachswisstopo et IGN-F sont des agences nationales CH/FR ; rien d'équivalent en Algérie. Le MNT viendra de Copernicus GLO-30 ou SRTM 30 m, l'ortho de Sentinel-2 (10 m, libre), Esri World Imagery ou Mapbox Satellite. Résolution visuelle plus grossière que la démo UTMB.
  • CoachVérifié en ligne, sur la zone : les tuiles DEM AWS terrarium au z14 fonctionnent sur Yakouren (gratuites, sans clé) ; l'Esri World Imagery est réelle jusqu'au z18 (~0,6 m/px) sur Ath Aïssi, le z19 est absent. Conclusion : pas besoin de Mapbox payant pour la vitrine.

Le POC : MapLibre sur données réelles

La discussion se solde par du code qui tourne sur le parcours réel, et par un pipeline reproductible dont le JSON alimente à la fois la carte et le profil.

  • ArbitragePOC livré : MapLibre GL JS 4.7.1 + raster-dem terrarium AWS + ortho Esri + profil SVG calculé hors-ligne depuis le même MNT. Parcours réel d'Ath Aïssi : 15,6 km, D+ 1 156 m, altitude 219–973 m, 6 checkpoints.
  • CoachPipeline reproductible : dem.py (lecture terrarium) + route.py (densification 45 m, lissage sur 5 points, D+ par segment) → parcours.json. Le même JSON alimente la carte 3D et le profil : source unique.
  • BossLe POC est validé. Demande : bandeau profil repliable pour laisser la carte seule en plein écran. Implémenté — en-tête cliquable, résumé km / D+ / nombre de points quand il est replié, map.resize au toggle.
  • BossStack validée : MapLibre GL JS 4.7.1 + Esri World Imagery (satellite) ou OpenTopoMap (topo) + AWS Terrain Tiles terrarium pour le relief. Répond largement au besoin, pas de Mapbox.

Synthèse — ce que la session a vraiment produit

Les trois apports structurants viennent du Boss : la référence UTMB, qui a tué le ruban .glb ; le ping GPS toutes les 10 minutes, qui a réduit le live à un point figé ; le statut associatif, qui a débloqué les licences. Restent trois liens non évidents.

LIEN 01

L'abscisse curviligne s est le vrai livrable d'architecture

Ce n'est pas un détail de rendu : s relie la carte, le profil altimétrique, les checkpoints de l'épopée 4 et les pings GPS sur une seule et même timeline. Une variable d'état, quatre surfaces.

LIEN 02

Le ruban .glb n'est pas mort, il s'est trompé d'épopée

Écarté pour la vitrine, il reste la bonne réponse pour l'app hors-ligne : là où MapLibre ne peut pas précharger de tuiles, un mesh pré-cuit de quelques Mo, versionné par course et mis en cache PWA, fait exactement le travail.

LIEN 03

Le profil repliable et le fallback 2D sont la même idée

Les deux disent que le couple (distance, altitude) est le socle et que la 3D est un bonus. Tout ce qui compte tient dans s et l'altitude ; le relief texturé vient par-dessus, quand la machine et la batterie le permettent.

Un brainstorming sur la 3D s'est terminé sur une variable scalaire : s, l'abscisse le long de la trace. Le reste — tuiles, mesh, exagération verticale — n'est qu'une façon de la regarder.
