## Constats réfutés (soupçonnés, puis prouvés faux)

1. **« Grille deux colonnes maintenue sous 960 px » (fenêtre 959,98-960).** Exact techniquement — la base (`globals.css:1255`) est en deux colonnes, le mobile dans `@media (max-width: 959.98px)` (`:1359`), le desktop dans `min-width: 960px` (`:1398`) — mais dans la bande de 0,02 px le titre `clamp(72px, 10.5vw, 136px)` tient sans débordement (~100 px à 959,99 px, colonne titre ~600 px). Convention standard anti-chevauchement, aucun mal démontrable.
2. **« Podium rendu au-dessus de "pas de classement" pour une épreuve non configurée ».** `Podium` retourne `null` sans ligne `rang !== null && statut === 'arrivé'` (`resultats-live.tsx`, composant Podium), et aucune arrivée rangée n'est démontrable pour une épreuve sans heure de départ configurée (c'est précisément le scénario du test de caractérisation : ces épreuves n'exposent rien au classement).
3. **« Slug sentinelle "toutes" déséfiltrable ».** Nécessiterait un admin créant une épreuve de slug `toutes` ; aucun chemin de données ne le produit. Défense théorique, pas un défaut atteignable.
4. **« Récursion infinie sur lien symbolique dans `css-sans-litteraux.test.ts` ».** `statSync` suit les symlinks, mais aucun symlink n'existe sous `apps/web/src` ; le test s'exécute dans le dépôt. Injoignable en l'état.
5. **« `socle.css` chargé globalement en contradiction avec ses commentaires ».** Le chargement global est un arbitrage documenté (spec 9.2 « conséquence assumée », entrée `deferred-work.md` §9.2) ; l'en-tête de `socle.css` dit « appliquée à aucun écran **dans cette story** [9.1] » — exact.
6. **« "Étape 0 sur 4" si aucune étape courante ».** Les trois seuls appelants (`inscription`, `acceptations`, `preuve`) posent toujours une étape `courante` (`git grep` à 78de2c6) ; le composant n'est utilisé nulle part ailleurs.
7. **« Deux instances du sélecteur d'épreuve se piloteraient mutuellement ».** Une seule instance du composant existe (accueil). Hypothétique.
8. **« L'incohérence de filtrage n'est tracée nulle part ».** Elle l'est : test « CARACTÉRISATION (à arbitrer) » + entrée dédiée dans `deferred-work.md` §9.5 (repris en I5 pour l'arbitrage restant).
